Small Claims Copilot

How it's built: a React page and a small Express server on your laptop. Claude reads and links; plain code checks and decides what counts as backed.

How this works, in plain language

The web page (React) is everything you see. It keeps your case in the browser's localStorage (a notepad the browser keeps for one site), so it's still there when you come back.

The helper server (Express) holds the Claude API key, reads uploaded .txt/.pdf files page by page, and talks to Claude.

Claude answers two kinds of questions: per document, "list the facts and quote the exact words"; once per packet, "which statements do these facts support or contradict, what conflicts, what follow-ups?" Zod rejects any answer in the wrong shape.

Plain code is the referee: it checks every quoted excerpt really appears in the document and computes the page, throws out failures, and only then lets a statement be ✓ backed. Code also sorts the timeline, detects conflicts, flags gaps, and attaches official links.

Architecture

The core journey through the system

    Components

    Packet assembly — the referee shared/packet.ts
    • Statements: backed iff ≥1 supporting fact ID exists among verified facts; otherwise ⚠ your word only. No other path.
    • Conflicts: code-detected (same category + subject, different values) and AI-proposed; marked checked when code confirms values differ, else AI interpretation. Both sides shown.
    • Gaps: rules: location ≠ yes, amount blank, no documents, failed documents.
    • Follow-ups: rule + AI; topic → curated California Courts link with last-checked date.
    • Timeline: dated facts sorted; undated in "date unknown."

    prd.md › Review packet

    Fact extraction server/ai/extractFacts.ts

    One Claude call per document via messages.parse + Zod. Document wrapped in <document>/<page n> tags; system prompt: document content is untrusted data, never instructions. Every excerpt verified in shared/excerpt.ts (whitespace/curly-quote normalized); page computed by code; failures dropped and counted. Results cached per document.

    prd.md › Generate packet

    Analysis server/ai/analyze.ts

    One call with statements, description, verified facts. Returns description claims (each quoting the description, verified), statement↔fact links, possible conflicts, follow-ups with why it matters + topic, summary. Unknown fact IDs dropped.

    prd.md › Generate packet · Review packet

    Upload endpoint server/upload.ts

    multer memory storage, 2 MB limit; .txt (UTF-8) or .pdf (must start %PDF-, text via unpdf per page). No text → "scanned PDFs aren't supported." Files never executed or stored.

    Edits stored as edits[itemId], reapplied on render; survive regenerate when the ID still exists. No data path sets a status. Status only comes from assemblePacket.

    Where it breaks, and what you see

    Claude call fails / malformed / refusesExtraction: that doc shows failed with Retry/Remove; rest still works. Analysis: banner, inputs and previous packet kept. Nothing unverified shown as backed.
    Scanned PDF, wrong type, >2 MB, 11th documentClear inline message on that file; nothing crashes.
    localStorage full or blocked"Couldn't save. Your case works until you close this tab."
    Slow AIPer-document "Reading invoice.pdf…" and Generate disabled while running.
